Set up your ERC workspace

This application starts empty. Configuration is managed by your administrator in the website files, rather than through a Connect button on staff screens.

1. Prepare Supabase

  1. Create a new project in Supabase.
  2. In SQL Editor, run supabase/001_install.sql from the full application package. For an existing 0.2.0 installation, run 003_contact_outcomes_upgrade.sql instead. Existing 0.3.0 databases need no schema change.
  3. In Authentication → Users, create your email/password account.
  4. Edit 002_add_members.sql with that email and your name, then run it to grant administrator access. Repeat with role staff for colleagues.

2. Set the public connection settings

Find the project URL and publishable key in Supabase's Connect dialog or API Keys settings. Edit the website's config.json:

{
  "supabaseUrl": "https://YOUR_PROJECT.supabase.co",
  "publishableKey": "sb_publishable_YOUR_PUBLIC_KEY"
}

Use only the publishable key. Never put a secret key, service-role key, database password or staff password in this file.

3. Publish with GitHub Pages

  1. Extract ERC-GitHub-Pages.zip.
  2. Create a new GitHub repository. Upload the extracted files so index.html and config.json are at the repository root. Keep the assets and vendor folders.
  3. Edit config.json with the settings above and commit the change.
  4. Open repository Settings → Pages → Deploy from a branch. Select main and /(root), then Save.
  5. Open the published HTTPS address. Sign in with your staff account.

Upload only the website ZIP contents. Workbooks, contact exports, database files and backups belong outside the website repository. The publishable key is public configuration; patient access still requires an active staff account.

4. Start with an empty workspace

After sign-in to a newly installed project, the lists are empty. Import the contact workbook first, worksheet بيانات التواصل الصحي, header row 1. Then import referal_master_sheet.xlsx → Follow_UP, header row 6. Preview, save source rows, and review a small sample before applying the remainder. The full import guide is included in the application package.

If this setup page keeps appearing, confirm that config.json was edited in the folder actually published by GitHub Pages. Reload after the deployment finishes.

Return to staff sign-in
